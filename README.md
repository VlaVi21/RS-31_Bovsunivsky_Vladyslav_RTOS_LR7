# RS-31_Bovsunivsky_Vladyslav_RTOS_LR7

**Номер групи:** РС-31

**Автор:** Бовсунівський Владислав

ОПЕРАЦІЙНІ СИСТЕМИ РЕАЛЬНОГО ЧАСУ ТА 32 БІТНІ  МК

**Лабораторна робота №7:** Налагодження середовища розробки для програмування
32-розрядних мікроконтролерів з використанням операційної системи реального часу. На
прикладі FreeRTOS.

**Обладнання:** STM32F411 BLACK PILL, CubeMX, STM32CubeIDE.

**Мета:** Ознайомитися з принципами роботи операційної системи реального часу
FreeRTOS, навчитися створювати та керувати потоками для керування світлодіодами на
STM32F411 Discovery.

__________________________________________________________________________________________

**Завдання до лабораторної роботи**: 

Варіант 2.  Створити три потоки для керування світлодіодами PD13, PD14, PD15. Частоти: PD13 — 10 
Гц (тривалість 50 мс), PD14 — 4 Гц (тривалість 150 мс), PD15 — 2 Гц (тривалість 300 мс). 
Кнопка PA0 змінює тривалість імпульсу PD13 від 50 мс до 200 мс.

---
### 👨🏼‍💻Функціонал:

**1. Multi-threading (FreeRTOS Tasks):** Створення 3-х незалежних потоків для світлодіодів PD13–PD15 та окремого потоку для моніторингу кнопки.

**2. Task Scheduling:** Використання планувальника для забезпечення заданих часових інтервалів:

- **PD13:** 10 Гц (50 мс затримка).

- **PD14:** 4 Гц (125/150 мс затримка).

- **PD15:** 2 Гц (250/300 мс затримка).

**3. Dynamic Parameter Control:** Використання глобальних змінних або черг для зміни vTaskDelay в потоці PD13 при натисканні кнопки на PA0 (перемикання між 50 мс та 200 мс).

**4. Hardware Abstraction:** Робота з периферією через STM32 HAL API.

---
### 🔵Підключення:

**1. Кнопки (Входи керування):**

- 1.1 GND - [-Key+] - PA0 (Pull_up)


**2. Світлодіоди:**

- 2.1 GND - [-LED+] - [резистор 325R] - PB15

- 2.2 GND - [-LED+] - [резистор 325R] - PB14
  
- 2.3 GND - [-LED+] - [резистор 325R] - PB13

### 🛠️ Налаштування периферії

У цій роботі реалізовано складну взаємодію між апаратними перериваннями та ядром ОС.

**Переваги обраної архітектури:**

**- Ефективність:** Завдяки семафорам потоки, що чекають своєї черги, перебувають у стані Blocked і не споживають ресурси процесора.

**- Безпека даних:** Використання черг гарантує, що дані від кнопок будуть передані коректно, навіть якщо потік у цей момент зайнятий іншою операцією.

**- Масштабованість:** Структура дозволяє легко додавати нові фази або змінювати логіку роботи кожного світлодіода окремо.

### ⁉️Як запустити:
1. Відкрийте проект у STM32CubeIDE/Keil.
2. Скомпілюйте проект (Build) та прошийте плату через ST-Link.
3. Після ініціалізації перший семафор xSemNext[0] примусово віддається (Give), щоб запустити цикл.
4. Потік RED бере семафор -> виконує роботу -> віддає семафор потоку YELLOW.
5. При натисканні кнопки на PA0, функція HAL_GPIO_EXTI_Callback відправляє нове значення затримки в xQueueLED[0].
6. Коли потік RED наступного разу отримає доступ до процесора, він забере нове значення з черги та змінить час свого горіння.
